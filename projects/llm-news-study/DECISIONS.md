"Adopted" means adopted for the design; no software implementation is implied. The earlier goal plans retain their historical decisions.

Build useful keyless primary-source paths first. | Permitted-use evidence and own-account capability test succeed. |

| D07 | Adopted | GDELT full history assumed -> historical capability unresolved | [2018 announcement](https://blog.gdeltproject.org/doc-2-0-updates-1-5-year-searching-and-updated-mobile-interface/) and [UI guidance](https://gdelt.github.io/) differ; historical probe returned 429. Recent probe succeeded. Saturated windows must report possible missing records. | Successful controlled historical probes and coverage audit. |
| D08 | Adopted | Drop Alpha Vantage outright -> reconsider as free challenger | [Official support](https://www.alphavantage.co/support/) advertises an educational/open-source exception to the ordinary free quota. Eligibility remains unverified. Finnhub/Marketaux are deferred, not declared universally unusable. | Confirm eligibility, history, rights, and incremental coverage. |
| D09 | Adopted | Fundus always first -> fixture-based routing by source/document type | [Current Fundus benchmark](https://github.com/flairNLP/fundus) and [Trafilatura evaluation](https://trafilatura.readthedocs.io/en/latest/evaluation.html) depend on versions/modes. SEC documents need structure-aware checks. | Compare saved-byte outputs on tuning and held-out fixtures. |
| D10 | Adopted | Closest Wayback after parser failure -> explicit cutoff-constrained archive acquisition | [Availability API](https://archive.org/help/wayback_api.php) returns a closest capture, which can be too late. A different source/capture must never be hidden by a parser fallback. | Archive evidence is insufficient; evaluate targeted Common Crawl. |
| D11 | Adopted | Name in headline/lead decides relevance -> evidence-based per-company assessment with uncertainty | Baseline is simple but misses relevant body references and ambiguous ticker contexts. Evaluate accepted and rejected samples; keep human labels separate. | Pilot precision/false-negative findings justify rule changes. |
| D12 | Adopted | MinHash then keep earliest copy -> retain copies; exact matching first; deduplicate only eligible versions in exports | Avoid destructive merging and future knowledge changing historical representatives. Choose near-duplicate method after observing actual scale/errors. | Exact matching leaves material syndication or event duplication. |
| D13 | Adopted | Primary/wire/commentary exclusive classes -> separate origin, document kind and distribution | A primary company release can also be wire-distributed. Publisher name alone does not classify every article. | Annotation reveals useful additional types. |
| D14 | Adopted | DuckDB mutable file read directly by UI -> SQLite operational state; optional DuckDB over frozen exports | [DuckDB embedded concurrency](https://duckdb.org/docs/2.0/connect/concurrency) does not fit independent writer/UI processes without extra coordination. [SQLite WAL](https://www.sqlite.org/wal.html) fits local readers and bounded writes; pin a build with the documented fix. | Measured workload exceeds SQLite or a deployed multi-user service becomes necessary. |
| D15 | Adopted | Permanent HTML for everything -> durable permitted original bytes, MIME-aware parsing, explicit retention limits | Unknown/forbidden retention cannot be promised away. Keep evidence without routine expiry where permitted; refusals/deletions have audit records. Free sources can still restrict sharing: see [Finnhub terms](https://finnhub.io/terms-of-service). | Source-specific rights evidence or storage capacity changes. |
| D16 | Adopted | Only accepted/rejected stage states -> durable operational states plus terminal disposition | Retry, cancellation and source outages are different from irrelevant content. Every returned discovery is accounted for; unknown missing articles are coverage gaps. | Failure-recovery tests reveal unaccounted transitions. |
| D17 | Adopted | 16:00 rule also determines prediction day -> actual session close, separate label deadlines | [Calendar library](https://github.com/gerrymanoim/exchange_calendars) provides schedules; exact-close/early-close rules must be explicit. Availability bucket is not a return interval. | New exchange/extended-hours profile or future label specification. |
| D18 | Adopted | Live mode and export last -> evidence capture and export invariants early | Prospective observations cannot be reconstructed later. Offer live capture only after first adapter's persistence/timing/recovery checks pass. No scheduled collection starts during planning. | Pilot/source readiness. |
| D19 | Proposed | Streamlit or similar -> Streamlit with durable jobs outside page reruns | Fits an initial local research UI. [Rerun semantics](https://docs.streamlit.io/develop/concepts/architecture/session-state) require a separate worker and database-backed progress/annotations. | User walkthrough or multi-user needs expose limitations. |
| D20 | Adopted | 100 positive/negative labels and coverage percentage -> stratified review, uncertainty and outage-aware denominators | Precision among accepted items misses false negatives; populated trading days do not estimate all-news recall. Start around 100 as a pilot, adjust to uncertainty. | Pilot variability and desired precision determine sample size. |
| D21 | Adopted | January 2025 + 90 days certifies clean April test -> unresolved experiment assumption | [Gemma report sections 2.4/3](https://arxiv.org/html/2607.02770v2) separate pretraining and instruction tuning. A margin cannot prove absence of later knowledge; Jan 31 + 90 days is May 1. | Goal 1 reviews exact checkpoint provenance and evaluation design. |
| D22 | Adopted | Historical provider sentiment baseline presumed safe -> separate versioned audit data, independently qualify baseline | Assignment/availability time is undocumented for old downloads; sentiment and reasoning stay out of model-facing exports. | A live observation or historical evidence establishes baseline availability. |
| D23 | Adopted | Firecrawl discarded as necessarily paid -> defer heavy service stack for scope/operations reasons | [Open-source self-hosting exists](https://github.com/firecrawl/firecrawl); no evidence yet that this project needs it. Browser rendering is an optional source-specific capability. | Measured pilot failures warrant a larger acquisition layer. |
